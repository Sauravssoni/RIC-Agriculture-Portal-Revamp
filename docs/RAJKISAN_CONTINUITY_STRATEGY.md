# RajKisan Continuity Strategy — Extend the Award-Winning Backbone, Do Not Replace It

## Strategic correction
Rajasthan already operates **RajKisan Saathi**, an integrated agriculture service platform. The strongest architecture for this challenge is therefore not a parallel agriculture super-app.

The Department's public web front door still has a different job: make services easy to discover, explain, prepare, continue and measure. RajKisan One is designed to make the public experience as coherent as the transaction infrastructure behind it.

```text
PUBLIC DEPARTMENT WEBSITE
legacy / content-oriented navigation
          ↓
RAJKISAN ONE
intent + discovery + continuity + rules + documents + feedback + observability
          ↓
EXISTING AUTHORITATIVE RAILS
RajKisan Saathi / RajSSO / Jan Aadhaar / Raj Sewa Dwaar / Raj eVault / RajDharaa / Sampark
```

RajKisan One owns the **experience contract**, not Government facts.

### It should own
- citizen-intent discovery and search;
- bilingual task journeys;
- personalised Action Centre;
- service continuity and resume state;
- deterministic non-statutory pre-checks;
- document-readiness orchestration;
- citizen-readable status translation;
- grounded chatbot explanations;
- first-party journey/feedback telemetry;
- content lifecycle and GIGW monitoring;
- cross-channel continuation across mobile, e-Mitra and selective SUTRA-assisted field access.

### It must not own
- statutory benefit approval;
- source land-record mutation;
- Farmer Registry authority;
- identity authentication authority;
- payment authority;
- authoritative scheme publication outside approved departmental workflow.

## Continuity with RajKisan Saathi v3.0
RajKisan One is complementary to future Farmer Databank, input/output management, facilitation, marketplace, AI/ML and GIS capabilities.

| RajKisan / future capability | RajKisan One front-door capability |
|---|---|
| Transaction processing | Citizen intent → correct transaction |
| Farmer data | Minimum-necessary personalised experience with consent |
| Workflow states | Plain-language timeline + next action |
| AI/ML decision support | Safe presentation of authorised outputs |
| GIS | Citizen service access + Department experience observability |
| Back-office analytics | Front-door completion, friction, search, feedback and content analytics |
| Multiple G2C/G2B/G2G services | One public information architecture and service catalogue |

## Migration strategy
1. **Wrap, do not rewrite:** index existing content and RajKisan service endpoints/deep links.
2. **Structure the high-value 20%:** convert priority schemes/services into versioned service objects.
3. **Dual publish:** maintain existing editorial operations while structured content becomes reusable.
4. **Connect approved APIs:** integrate through Raj Sewa Dwaar / Department-approved interfaces.
5. **Retire duplication only after evidence:** migrate legacy pages only when usage, parity and owner sign-off are proven.
