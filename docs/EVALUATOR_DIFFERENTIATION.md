# Evaluator Differentiation — Why This Is More Than a Standard Portal Revamp

## Baseline submission pattern
A competent submission can satisfy the literal brief with:

```text
responsive website
+ Hindi/English
+ chatbot
+ eligibility form
+ upload
+ SSO mock
+ page-view analytics
```

That is necessary, but no longer differentiating.

## RajKisan One differentiators

### 1. State-investment continuity
Preserve and extend RajKisan Saathi instead of proposing a competing agriculture platform.

### 2. Intent-to-outcome architecture
Start from **what the farmer is trying to do**, then route to the correct existing Government service.

### 3. Personal Action Centre
After consented sign-in, surface pending verification, missing documents, approaching deadlines, new status receipts and relevant services.

### 4. Deterministic Scheme Compiler
Published scheme criteria become versioned machine-readable rules. AI can draft/explain, but an authorised human publishes the rule version and the authoritative Department workflow retains final sanction.

### 5. Document readiness, not upload repetition
Reuse verified records first through approved Raj eVault/DigiLocker rails; upload only what is missing. Evaluator mode validates file type/size and computes SHA-256 locally without transmitting the file.

### 6. Cross-channel continuity
The same service contract can continue across mobile/PWA, desktop web, e-Mitra, extension-worker assistance and selective SUTRA-ID Edge use.

### 7. Analytics becomes an operating queue

```text
zero-result search
→ content gap
→ owner
→ due date
→ publish fix
→ verify completion improvement
```

The same loop applies to document drop-off, login friction, translation gaps, broken links and accessibility defects.

### 8. GIGW as runtime governance
Each priority page/service carries owner, review date, language parity, source version, archival/supersession state and quality-monitoring status.

### 9. Truthful interoperability
Every connector has a visible truth state. The prototype never fabricates privileged Government credentials.

### 10. Low-bandwidth and assisted-first design
The app is a lightweight static PWA plus deterministic APIs, designed to degrade gracefully instead of requiring a heavy application framework.

### 11. Citizen Service Contract
A scheme page is executable and accountable: owner, availability, pre-check, evidence, source/version, next step, decision authority, channel continuity, escalation and freshness.

### 12. Cross-channel resume receipt
The MVP creates a privacy-safe minimum-context continuation receipt so a journey can move from self-service web to an assisted channel without restarting.

## Evaluation thesis

> **The best portal is not the one with the most features. It is the one that makes existing Government capability easiest to discover, safest to compose, simplest to complete and easiest for the Department to continuously improve.**
